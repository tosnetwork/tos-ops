## Stops and corrections retained

The initial source-clock call used milliseconds where this local source RPC
expects seconds. The pending deployment at nonce 10 was verified against its
journaled input, and the timer was corrected to one second. The original
transaction was included; there was no second deployment.

The first mint qualification treated the raw RPC stack as tuple order. It
stopped without another send. The shared checkpoint reader now normalizes the
stack once for every getter. Read-only qualification confirmed the minted
amount. A regression test and a stack-order mutation cover that boundary.

64 source blocks. The collector correctly became stale. An attended read-only
source audit covered blocks 624-862 in bounded chunks, retained every chunk and
its endpoint hashes, found no balance/pause/destruction events and evaluated the
complete interval through the existing checker. The original baseline was kept.
Continuous collection then resumed. This local audit is not a delivered or
reviewed production gap-reconciliation procedure; that remains a separate gate.

## Re-run the preparation

Use the existing local network and private directories. Build the local source
fixture with `local/contracts/test-usdt/build.cjs SOLC_MODULE ARTIFACT`; retain
its successful build log. The deployment driver requires explicit approved
paths and defaults to a dry run for value steps:

```sh
python local/scripts/local-pq-usdt.py namespace \
  --data "$DATA" --source-state "$USDC_STATE" --state "$USDT_STATE" \
  --artifact "$ARTIFACT" --build-log "$BUILD_LOG" \
  --tos-root "$TOS_ROOT" --tosctl "$TOSCTL"
```

After reviewing the dry run, the same command with `--execute` performs or
reconciles the journaled deployment. `clock --execute` enables one-second local
source blocks; `mint --execute` caps, approves, locks and mints; `qualify` is
read-only; `prepare` builds the append from the deployed addresses. `adopt`
quotes the current critical rules, and `adopt --execute` uses the existing
operations journal and independently archives each registration/vote. Never
continue past an unresolved intent. Funding needs the existing faucet interlock;
this driver does not stop an election task or fund a payer automatically.

The source monitor is `local/scripts/local-settlement-monitor.py --help`.
It requires a source bridge runtime pin checked against the pinned build,
the compiled fixture and both run states. Its policy scope cannot change
silently. Run continuously once the initial interval is accepted; a stale
report cannot authorize work. Keep the pending production scale and gap gates
in [the monitor runbook](../../../testnet/settlement-monitor.md).

Verification uses the repository's normal environment:

