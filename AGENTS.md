# Working in this repository

This private repository holds the team's node service settings, operating
documents and scripts, one subdirectory per network (`local/`, `testnet/`,
`production/`). See [README.md](README.md) for the layout.

## Commit directly to `main`. Do not open pull requests.

Commit and push straight to `main`. Do not create branches or pull requests
here; there is no review gate. If someone else pushed first, rebase onto
`origin/main` and push again.

Push in the same session that commits. A commit left unpushed is lost when a
machine or worktree goes away.

## Never commit secrets

No SSH keys, private keys, consensus or controller root seeds, wallet keys,
console or edge tokens, TLS private keys or certificates. `.gitignore` blocks
the usual file names, but read every staged change before committing. Fixture
seeds generated by the local network stay under `/data` on the host.

Do not write a personal home path, user name or e-mail address into a file
here. Use `$HOME`, `$TOS_ROOT` or a placeholder.

## Other rules

- Write everything in English.
- Scripts that need tos code or binaries find the checkout through `TOS_ROOT`.
  Run the tests in `local/tests` against the tos revision you changed things
  for, and name that revision in the commit message.
- Keep development-only material (deterministic seeds, faucet wallets, the local
  drivers, acceptance-only options) out of `testnet/` and `production/`.
- `testnet/` tests need only pytest: `"$TOS_ROOT/.venv/bin/python" -m pytest -q testnet/tests`. Its
  end-to-end check is `testnet/scripts/rehearse-loopback.sh`; name the tos
  revision it passed on in the commit message.

`CLAUDE.md` is a symlink to this file, so every agent reads the same
instructions.
